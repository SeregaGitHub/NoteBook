В Java, как и в любой многопоточной среде, взаимная блокировка (deadlock) возникает, 
когда два или более потоков навсегда блокируют друг друга, 
ожидая освобождения ресурсов, захваченных другими потоками. 
Для возникновения deadlock необходимо одновременное выполнение четырёх условий (условия Коффмана):

* Взаимное исключение – ресурс не может быть использован одновременно несколькими потоками.

* Удержание и ожидание – поток удерживает один ресурс и ожидает получения другого.

* Отсутствие принудительного освобождения – ресурс нельзя забрать у потока, он освобождается только добровольно.

* Циклическое ожидание – существует цикл из потоков, каждый из которых ждёт ресурс, удерживаемый следующим потоком в цикле.

Чтобы решить проблему deadlock, можно воздействовать на любое из этих условий. Основные подходы:

1. Предотвращение (Prevention)

* Нарушение условия взаимного исключения

Сложно реализовать для большинства ресурсов, 
но можно использовать lock-free алгоритмы и структуры данных из пакета java.util.concurrent 
(например, ConcurrentHashMap, AtomicInteger), которые минимизируют блокировки.

* Нарушение условия удержания и ожидания

Захватывать все необходимые блокировки атомарно, например, через общий объект-координатор или специальный менеджер блокировок.
Использовать паттерн «двухфазная блокировка»: сначала запросить все блокировки, и только потом начать работу. 
Если хотя бы одну получить не удалось – освободить все и попробовать снова.

* Нарушение условия отсутствия принудительного освобождения

Использовать Lock из java.util.concurrent.locks с методами tryLock() или tryLock(timeout, unit). 
Если поток не может получить блокировку, он освобождает уже удерживаемые и повторяет попытку позже или завершает работу.

* Нарушение условия циклического ожидания

Установить глобальный порядок получения блокировок. 
Все потоки должны захватывать блокировки строго в одном и том же порядке 
(например, по идентификатору объекта или по заранее определённой иерархии). 
Это исключает цикл.

2. Избежание (Avoidance)

Использование алгоритмов, которые динамически анализируют запросы на ресурсы 
и не допускают возникновения цикла (например, алгоритм банкира). 
На практике в Java применяется редко из-за сложности и накладных расходов, 
но может быть реализован для специфических систем с предсказуемыми запросами.

3. Обнаружение и восстановление (Detection and Recovery)

Если предотвратить deadlock невозможно, можно его обнаружить и принять меры:

Обнаружение:

Использовать ThreadMXBean.findDeadlockedThreads() для программного поиска заблокированных потоков.

Внешние инструменты: jstack, jconsole, VisualVM, которые показывают состояние потоков и обнаруживают циклы ожидания.

Восстановление:

Прервать один или несколько потоков, участвующих в deadlock (метод interrupt() или Thread.stop() – последний не рекомендуется).

Освободить ресурсы принудительно (если это возможно, например, через Lock.unlock() в другом потоке, но это опасно).

Перезапустить потоки или всю систему (грубый, но иногда единственный способ).

4. Использование высокоуровневых средств синхронизации

Предпочитать ExecutorService и задачи (Callable, Future) вместо ручного управления потоками.

Использовать java.util.concurrent коллекции и атомарные классы, которые внутренне реализуют эффективные неблокирующие алгоритмы.

Применять CountDownLatch, CyclicBarrier, Semaphore для координации без явных блокировок.

5. Практические рекомендации
Минимизировать количество блокировок и время их удержания.

Не вызывать чужой код (например, методы колбэков) под блокировкой – это может привести к непредсказуемым захватам.

Избегать вложенных блокировок, если это возможно.

Использовать ReentrantLock с tryLock и таймаутом вместо synchronized, когда нужна гибкость.

Тщательно документировать порядок получения блокировок в коде.

Пример: deadlock и его устранение с помощью порядка блокировок

Проблемный код:

public void method1() {
    synchronized (lockA) {
        synchronized (lockB) { ... }
    }
}

public void method2() {
    synchronized (lockB) {
        synchronized (lockA) { ... }
    }
}

Решение:

public void method1() {
    synchronized (lockA) {
        synchronized (lockB) { ... }
    }
}

public void method2() {
    synchronized (lockA) {   // всегда сначала lockA
        synchronized (lockB) { ... }
    }
}

Или с использованием ReentrantLock и tryLock:

Lock lockA = new ReentrantLock();
Lock lockB = new ReentrantLock();

public void method() {
    while (true) {
        if (lockA.tryLock()) {
            try {
                if (lockB.tryLock()) {
                    try {
                        // работа с обоими ресурсами
                        return;
                    } finally {
                        lockB.unlock();
                    }
                }
            } finally {
                lockA.unlock();
            }
        }
        // небольшая пауза перед повторной попыткой
    }
}
